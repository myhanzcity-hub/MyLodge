5. URL·언어·앵커 계약
현재 상세 주소는 domestic-villas.html과 business-valley.html. 이름을 바꾸려면 메인·상세·공유 링크·언어 경로와 호환 방식을 함께 결정한다.
메인→상세
- 주문진: domestic-villas.html#project-jumunjin
- 양양: domestic-villas.html#project-yangyang
- 국내 개요: domestic-villas.html#side-parks
- 국내 공용 시설: domestic-villas.html#domestic-facilities
- 치앙마이: business-valley.html 및 필요한 내부 장면 앵커
상세→메인: index.html#brand-paths 사용 중. 동료 메인에 #brand-paths가 존재하는지 먼저 확인하고, 바꿨다면 새 복귀 앵커와 모든 상세 링크를 함께 수정한다.
현재 우리 로컬 메인은 chairman.js가 이 영역을 동적으로 생성한다. index.html 정적 텍스트에서id를 찾지 못했다고 링크 오류로 판정하지 않음. 실제 영문 실행 화면에서#brand-paths, 국내·치앙마이 링크와lang=en을 확인했다. Hojiakbar 새 메인까지 확인한 것은 아님.
언어: 내부 이동의 ?lang=en 보존. KO 복귀 시 lang=en 제거. 현재 구역 hash는 유지. 화면 보기의 screen-frame은 기존 뷰어 컨텍스트일 뿐 일반 진입의 필수 파라미터가 아님.
과거 국내 시설 주소: jumunjin-/yangyang-와 beach/party/club/terrace/market/concierge 조합을 공용 카드 별칭으로 유지. 외부 공유 주소를 조용히 끊지 않음.
해외 치앙마이를 국내 목록 안에 넣지 않는다. 국내/해외 라벨과 상호 이동은 각각 구분.
현재 한즈시티 연결: https://hanzcity.com/chiangmai/intro. 목적지 표시 확인. 한즈시티 기능·API 연동을 이번 파크 통합에 새로 추가하지 않음.

6. 통합 작업 순서 제안 — 오늘 실행하지 않음
1) 양쪽 미커밋 변경을 먼저 보존하고, 통합에 사용할 정확한 커밋을 서로 확인한다. 사용자 검토·승인 없는 오늘 커밋/푸시는 하지 않는다.
2) 별도 통합 검토 브랜치 이름과 시작점을 회의에서 결정한다. 운영 main으로 바로 덮어쓰지 않는다.
3) 메인/인트로와 파크 전용 파일을 각 담당자가 설명하고, 공통 파일의 양쪽 변경을 줄 단위로 검토한다. ours/theirs 일괄 선택으로 상대 작업을 지우지 않는다.
4) 이미지·CSS·JS 공개 목록을 합치고 같은 이름의 다른 파일은 해시·실제 이미지를 비교한다. 내부 원본과 보고서를 dist에 넣지 않는다.
5) 아래 수용 기준으로 통합 실행본을 검수한다. 실패 항목은 고친 후 관련 범위를 다시 확인한다.
6) 결과·미결 항목·통합 SHA를 기록한다. 운영 배포는 공개 범위·승인 담당·미확정 정책 안내를 별도 확인한 뒤 사용자 지시에 따른다.

7. 통합본 수용 기준
A. 콘텐츠 보존
- 메인·인트로의 동료 변경이 남아 있고 파크 최신 변경도 누락되지 않음.

- 치앙마이 활기 있는 초반3장, 세계 음식 최종 인물 없는5분할 페이드, 첨단 비즈니스 엔딩 유지.
- AI 콘셉트/실제 운영 미확정 안내 유지. 수익·연간 행사·의료 서비스 등을 검증된 사실처럼 새로 넣지 않음.
B. 이동·언어
- 메인에서 국내·해외 목적지 인식, 상세 진입1회 클릭, 각 파크→다른 파크→메인 복귀.
- KO/EN 언어·hash 유지, 기존 국내 공유 앵커, 목차 현재 위치, 메뉴 상호 닫힘.
- 인트로 건너뛰기·뒤로가기·언어 전환과 전경 창 열기/닫기/원본 보기/Esc/초점 복귀.
C. 화면·기술
-320·390·768·1024·1280px 주요 화면과 짧은 가로/세로 전경 창. 메뉴·언어 패널 겹침과 모바일 버튼 잘림 없음.
- JavaScript 문법·기존 가상 모델·공개 빌드·파일 목록 확인. 통합본의 새 파일을 포함해 누락0·중복0·내부 노출0을 확인한다.
- 일반 Chrome의 화면 보기→자동 전환 콘솔 확인. 이번 치앙마이에서는 미재현이나 이전 국내 기록 원인 확인은 남음.
- 실기기/Safari/스크린리더를 검수하지 못하면 미검수로 기록하고 담당·후속 확인일을 지정한다.

11. 공통 코드 검토 시 유지할 동작
detail-pages.js
- 언어 번역 후 내부 링크에 lang=en을 붙인다. 같은 문서의#앵커와 언어 선택 링크는 별도 처리한다. 새 메인 라우팅 방식과 다르면 이 규칙을 설명하고 맞춘다.
- 목차의 href는 현재 '#구역ID' 형태다. 도입 장면과 공용 시설 별칭을 부모 목차 항목으로 매핑한다. 통합 과정에서 목차 링크를 절대 URL로 바꾼다면 현재 위치 비교도 확인한다.
- 사진 실패 안내는 이미 figure에 안내가 있으면 중복 추가하지 않는다. load 시 실패 class와 안내를 지우고, 다시 실패하면 다시 안내한다. once:true를 되살리면 반복 실패를 처리하지 못할 수 있다.
- 사진 처리 대상은 현재 figure 내부의 .scene-frame/.experience-panel/.park-card 이미지다. 마크업을 바꿀 때 figure 구조와 대체 텍스트를 함께 확인한다.
park-feedback.js
- data-park-panorama 링크만 강화하고, 기본 href는 원본 사진으로 유지한다. dialog 미지원 또는 스크립트 미실행 환경의 원본 링크를 지우지 않는다.
- Ctrl/Command/Shift 등 수정키 클릭은 일반 링크 동작으로 넘긴다. 모든 클릭을 무조건 차단하지 않는다.
- 로딩/실패/재시도 때 disabled·hidden 상태가 달라진다. 초점 순환은 현재 보이고 활성인 버튼/링크/이미지영역만 포함한다. 실패 상태에서 비활성 확대 버튼을 초점 대상으로 복원하지 않는다.
- 닫을 때 원래 버튼 초점 복귀, 확대 상태 초기화, 본문 스크롤 잠금 해제를 유지한다. 새 메인 모달과 중복으로 초기화하지 않는다.
park-feedback.css
- 전체 문단 규칙이 전경 도움말·안내의 작은 글자 규칙을 덮던 충돌을 이미 수정했다. 통합 후 낮은 화면에서 다시 큰 본문 글자로 바뀌지 않는지 확인한다.
- 모바일 영문 치앙마이 H1과 p.eyebrow 보완은 상세 페이지 범위다. 메인 전체 제목 크기를 바꾸는 규칙으로 옮기지 않는다.
- 국내 시설 별칭은 위치·스크롤 여백을 가진 비어 있는span이다. 보이는 중복 제목으로 만들거나 존재 자체를 삭제하지 않는다.
공개 파일 목록
- data-panorama 링크의 원본 크기, img src, srcset3종 모두 실제 목록에 있어야 한다. 960px 파일만 합치면 원본 전경이나 모바일 변형이 빠질 수 있다.
- 원본 PNG와 선택되지 않은 치앙마이 시안12개는 현재 공개 목록에 없다. 파일이 로컬에 있다는 이유로 자동 추가하지 않는다.

12. 통합 후 빠르게 재현할 핵심 사례
1) EN320 첫 치앙마이 화면에서 전경 버튼이 나타나고 제목이 잘리지 않는지.
2) #yangyang-beach 과거 주소가 공용 비치 카드로 이동하고 목차가 Shared facilities인지.
3) 모바일 메뉴를 연 뒤 언어 패널을 열면 메뉴가 닫히고 메뉴 버튼 이름이 선택 언어로 맞는지.
4) 치앙마이 EN→양양→치앙마이 이동에서 lang=en이 유지되는지.
5) 전경 창에서 Shift+Tab/Tab·Esc·원본 보기·맞춤·초점 복귀·본문 잠금 해제를 확인.
6) 별도 테스트 환경에서 사진 실패→복구·재실패 시 안내 중복/잔여가 없는지. 실제 공개 원본 파일을 지우며 시험하지 않음.
7) 공개 빌드의 이미지·스크립트·스타일 누락, 내부 자료 노출이 없는지.
8) 새 메인/인트로의 원래 동작과 상세 복귀 링크가 둘 다 유지되는지.
