# 추가 개선 — 상담으로 이어지는 흐름

요청: “20분 줄테니까 좀 더 고민해서 개선해봐.”
작업 시작: 2026-09-29 12:23 KST.
작업 마무리: 2026-09-29 12:43 KST. 약 20분 동안 기획 대조, 구현, 화면 검토와 기록을 진행했다.

## 이번 판단

앞선 수정은 입력 오류·재연락 누락·파일 용량을 줄이는 작업이었다. 이번에는 **정보 탐색 → 관심 내용 선택 → 상담에 가져오기 → 작성 내용 확인** 사이의 연결을 보완했다. 새 기능 수를 늘리는 것보다 이미 읽고 선택한 내용을 다시 입력하지 않게 하는 데 우선순위를 뒀다.

## 구현 내용

### 1. 희망 시간 선택

- 이전·다음 7일 탐색, 표시 날짜 범위, 오늘부터 보기, 선택한 날짜로 돌아가기.
- 날짜 목록을 둘러보는 동작은 이미 선택한 날짜·시간을 바꾸지 않는다.
- 실제 날짜를 바꾸면 시간대·시각을 해제하고 재선택 안내를 제공한다.
- 시간 무관으로 전환했다가 날짜 선택으로 돌아오면 이전 날짜·시간을 복원한다. 명시적인 ‘시간 선택 해제’는 이 임시 기억도 지운다.
- 당일 시간대는 이미 지난 시각을 제외한 범위를 표시한다. 지나간 선택을 임의의 새 날짜로 바꾸지는 않는다.
- 추가 정보에서 희망 시간을 가장 먼저 배치했다. 요약은 `2026. 9. 30(수) · 오후 2시 희망` 형식이다.
- 09–23시는 계속 화면 예시다. 운영일·휴일·마감·예약 확정 정책을 새로 정하지 않았다.

### 2. 작성 부담과 입력 보존

- ‘예시 이름·번호로 체험하기’는 빈 이름·번호만 채운다. 기존 입력·동의 선택을 바꾸지 않는다.
- 접힌 추가 정보에 시간·주제·서비스·문의 작성 여부를 보여준다. 많은 서비스는 첫 항목과 나머지 개수로 짧게 표시한다.
- 모바일 입력 글자를 16px로 조정하고 선택 칩·날짜 이동의 터치 영역을 확보했다.
- 개인정보를 브라우저 영구 저장소에 보관하지 않는다. 다시 열거나 새로고침하면 입력은 유지되지 않는다.

### 3. 서비스·FAQ에서 상담으로 연결

- 네 준비 중 서비스에 ‘상담에 관심 내용 담기’ 추가. 해당 관심 서비스만 선택하고 나머지 입력은 유지한다.
- FAQ 답변에 ‘이 질문을 상담에 담기’ 추가. 빈 문의에는 질문을 넣고, 작성 중이면 기존 내용 뒤에 덧붙인다.
- 같은 질문은 중복 추가하지 않는다. 1,000자를 넘으면 기존 내용을 보존하고 추가하지 못한 이유를 안내한다.
- 이미 고른 상담 주제는 유지한다. 주제가 비어 있을 때만 질문 분류에 맞춰 선택한다.
- 상담 폼으로 이동할 때 키보드 포커스도 함께 이동한다. 실제 접수·전송은 없다.

### 4. FAQ 탐색

- 질문과 답변을 함께 검색. 공백·쉼표·가운뎃점·물음표 차이를 정리한 뒤 비교한다.
- 기존 분류 필터와 검색을 함께 적용한다. 한글 조합 중에는 필터를 갱신하지 않는다.
- 빈 결과, 검색어 지우기, 전체 질문 보기 제공.
- 특정 분류에서 결과가 없으면 검색어를 유지한 채 전체 분류로 넓혀 볼 수 있다.
- 검색어는 주소·저장소·서버에 기록하지 않는다.

### 5. 운영 시안

- 문의 목록에 다음 행동과 일정 미정 사유를 표시한다. 긴 내용은 두 줄로 표시하고 상세에는 원문을 유지한다.
- 최근 접수순 / 연락 일정순 선택. 일정순은 빠른 일정부터, 미정은 뒤로, 종료 문의는 마지막에 둔다.
- 정렬 변경도 기존 미저장 보호를 거친다. 같은 필터를 다시 선택하면 편집 화면을 재생성하지 않는다.
- 분 단위 목록 갱신 시 모바일 목록의 가로 스크롤 위치도 유지한다.

### 6. 접근성과 시각적 마감

- 키보드용 본문 바로가기, 모바일 메뉴에서 목적지로 포커스 이동.
- 긴 페이지·입력란·안내창에 얇은 스크롤바를 제공해 더 읽을 내용이 있음을 알린다.
- 첫 화면에 ‘사전 안내 단계 · 상담 화면 체험 가능’을 표시해 현재 공개 범위를 앞에서 알린다.
- 기존 녹색 계열·콘셉트 사진·숫자 애니메이션·스크롤 효과는 유지한다.

## 범위와 확인

로컬 프런트엔드와 메모리 운영 시안의 변경이다. 실제 서버·저장·인증·알림·결제, GitHub 반영·배포는 보류한다. JS 문법 확인과 공개 빌드 생성, 화면 미리보기 범위로 마무리하며 기존 자동 회귀 검사 묶음은 실행하지 않는다. 실제 접수 시작 전 종합 검증이 필요하다.

실행 결과: app.js, consultation.js, workflow.js 문법 확인과 공개 빌드 성공. 공개 산출물은 22개 파일이다. 화면 기록은 프로젝트 상위 `review/refinement-20260929-mobile.png`, `review/refinement-20260929-faq.png`에 보관했다. 모바일 390px·PC 1280px 폭에서 화면을 살펴본 뒤 임시 뷰포트 설정은 해제했다. 이 기록은 모든 기능의 회귀 검증을 통과했다는 의미가 아니다.

## 이번에 추가하지 않은 것과 이유

- 별도의 자체 달력: 기본 달력과 주 단위 탐색으로 요구를 충족하므로 새로운 키보드·날짜 접근성 규칙을 늘리지 않았다.
- 입력 자동 저장: 현재는 체험 단계이고 개인정보 보관 정책이 미정이므로 메모리 안에서만 선택을 유지한다.
- 확정되지 않은 프로젝트 비교 지표: 실제 정보 차이가 생기기 전에는 미정 정보를 반복하는 표를 추가하지 않았다.
- 예약 가능일·담당자 응답 시간의 약속: 승인된 운영 달력이 없으므로 날짜 선택을 확정 예약처럼 표시하지 않는다.
