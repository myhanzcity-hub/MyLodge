# 모바일 개선 기획의 관찰 근거

2026-10-09 수집. 제품을 새로 수정한 결과가 아니라 기존 개발본의 자료 수집·비교 관찰이다.

## 환경

- 최신 개발본: `github-sync/MyLodge_Business`.
- 비교 화면: `http://127.0.0.1:4186/`의 모바일 보완본. 실제 휴대폰이 아닌 Codex 데스크톱 브라우저의 iframe 검토실이다.
- nominal 크기 390/320/768/844/1440px와 document clientWidth는 다르다. 이 환경에서는 스크롤바로 clientWidth가 10px 작았다.
- 밝음/어두움은 검토실의 테마다. OS 선호·브라우저 강제 다크와 구분한다.
- 확대는 `--review-text-scale`을 사용하는 선택된 텍스트에만 적용된다. OS 글자 확대·핀치줌·전체 브라우저 줌 결과가 아니다.
- root와 lab의 app/intro/editorial/localization/mobile-layout CSS/JS/branding 7파일은 SHA256 일치를 확인했다. index.html은 검토실 설정 전달용 mobile-improvements.js를 추가 연결한 차이가 있다. 이 스크립트는 테마/배율 전달용이다.

## 확인한 문제·보완 후보

1. **이미지 슬롯과 sizes 불일치:** 844px 가로에서 서비스/오너/분위기 카드의 사진 폭 792px. 최종 선언은 45vw다. 초기 관찰의 서비스 currentSrc는 480.webp였으나, 넓은 화면에서 돌아오는 경로에서는 960.webp가 유지됐다. 캐시·이전 자원 선택을 분리해야 한다. 480 서비스 파일의 실제 픽셀 폭도 480이다.
2. **생활 이미지의 과거 배경 기준:** editorial.js에서 모바일 1152px 등의 sizes를 사용하지만 현재 모바일 사진은 정상 흐름의 16:10 영역이다. 다운로드 비용과 실제 화질을 비교할 후보다.
3. **사진 캡션의 높이 변화:** 320px 영문에서 사진은 156.375px로 안정적. 하단 영역은 46.1875/69.28125px로 달라져 약 23px 위치 변화가 있었다. 구간 전체의 CLS 수치를 측정한 것은 아니다.
4. **영문 접근성 역할 설명:** 영어 label과 함께 한국어 aria-roledescription이 남았다. 실제 보조기술 낭독 결과는 미실시다.
5. **확대 범위의 차이:** 검토실 200%에서 생활 제목/본문은 확대되지만 사진 버튼 13px·캡션 14px는 유지됐다. 검토실 점검 범위를 보완해야 한다.
6. **영상 속 카피:** 한국어·영어 모바일 영상 모두 실제 720×1280, 30초 loop다. 영상 안의 글자는 HTML 확대에 반응하지 않는다. 기존 모바일 자산을 인정하고 읽기 대안을 먼저 검토한다.
7. **가로·태블릿의 길이:** 영어 기본 글자 서비스 구간은 PC 약 882px, 390px 약 1665px, 768px 약 2287px, 844px 약 2439px. 긴 길이를 잘림으로 오판하지 않고 사진 높이/본문까지의 거리를 사용자 관찰로 판단한다.
8. **메뉴 뒤 움직임:** 안정된 로드 후 메뉴 hidden=false를 확인한 상태에서 생활 장면 번호가 바뀌었다. 메뉴 읽기 중 배경 움직임의 영향과 제어 정책을 검토한다.
9. **초점과 자동 재생:** 정지 버튼에 키보드 초점만 두면 생활 장면 전환이 계속됐다. APG와의 차이이며 이 사실 하나로 사이트 전체 WCAG 실패를 선언하지 않는다.

## 유지할 동작

- 표본 조건의 생활 장면 전환에서 활성 장면은 하나였고 높이가 안정적이었다.
- 한국어 생활 정지 후 가로 전환에서도 정지 상태·번호가 유지됐다.
- 첫 영상은 4.473855초에 사용자가 정지한 뒤 가로 자산 전환과 17초 관찰, 세로 복귀에서도 같은 시점을 유지했다.
- 사진 덱의 숨은 장면은 inert와 aria-hidden=true 상태였다.
- 화면 밖 갤러리는 전환하지 않고 구간에 다시 들어오면 전환했다. 화면 밖 정지를 오류로 세지 않는다.

## 해석에 필요한 주의점

- `initial-menu-attempt-not-open` 표본은 메뉴가 실제로 열리지 않았으므로 열린 메뉴의 근거로 쓰지 않는다. `menu-open-confirmed`만 열린 상태의 증거다.
- `320-en-200-life-start`는 초기 설정 전달과 로드가 진행 중인 표본이다. 이후 200%가 반영된 장면 높이 1067.703125px와 구분한다. 설정 전후 높이 변화와 슬라이드 전환 높이 변화를 혼동하지 않는다.
- 이전 화면에서 받은 큰 파일을 유지할 수 있다. currentSrc만 보고 매번 같은 파일을 강제해야 한다고 판단하지 않는다.
- lazy 이미지의 currentSrc가 비어 있는 화면 밖 표본은 로드 실패의 증거가 아니다.
- scenic backdrop의 큰 rect는 의도된 cover/clip과 비교해야 한다. 활성 본문이 문서 폭을 넘는 문제와 구분한다.
- 서비스 카드가 반투명이고 뒤에는 사진·shade가 있다. section background 두 색만 계산해서 대비 통과/실패를 선언하지 않는다.

## 이번 관찰로 판정하지 않은 항목

실제 iOS/Android/삼성/인앱 재생 정책, 강제 다크 변환, 주소창·노치·키보드·핀치줌, VoiceOver/TalkBack 낭독, 실제 사용자 Web Vitals, 고령 참여자 과제는 미실시다. 기획서의 시험 과제로 남겼다.
