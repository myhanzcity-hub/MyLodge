## 요약

현재 스타일은 유지할 만하다. 다음 작업의 우선순위는 **입력 보존 → 메뉴 상태 → 재연락 누락 → 중요 안내 가독성 → 설명과 이미지 경량화**다.

## 3. 디자인·사용성 개선 제안

### 1) 사진을 유지하면서 파일 크기를 줄인다

PNG 5장의 합은 14,871,992바이트(약 14.9MB), 첫 사진은 3,011,637바이트(약 3.0MB)다. 화면에는 크기별 이미지 선택이 없다. 나머지는 lazy loading이므로 14.9MB가 전부 첫 화면에서 다운로드된다는 뜻은 아니다.

WebP/AVIF와 모바일·PC 크기를 준비하고 `srcset/sizes`를 적용한다. 원본 PNG는 편집용으로 보관한다. 첫 사진의 AI 콘셉트 표시와 현재 스타일은 유지한다. 실제 느린 연결의 LCP/FPS는 측정하지 않았으므로 개선율은 약속하지 않는다.

### 2) 첫 방문 경로의 반복 설명을 줄인다

390×844px, 상세와 추가 입력이 접힌 기본 상태의 전체 페이지는 약 17,768px다. 단순 나눗셈으로 약 21화면 분량이다. 준비 중 서비스 약 3,126px, 그 다음 회원 서비스 약 931px가 연속된다.

권장 순서: 첫 소개 → 공동소유·비용 → 프로젝트 → 참여 전 확인 → 준비 중 서비스 → FAQ·상담.

- 네 가지 준비 중 카테고리는 유지한다.
- 카테고리마다 첫 설명은 한 문장과 핵심 항목만 남기고 자세한 조건을 펼치기로 제공한다.
- 회원 화면 예시는 해당 카테고리 안에서 펼쳐 보게 하여 설명의 반복을 줄인다.
- 참여 절차와 상담 절차는 서로 다른 단계라는 표시는 유지하면서, 반복되는 접수 안내 블록을 줄인다.
- 현재 위치를 메뉴에서 표시하면 긴 페이지를 돌아다닐 때 위치를 잃기 어렵다.

### 3) 모바일 날짜 선택을 더 넓고 명확하게 만든다

320px에서는 날짜 7개를 한 줄에 넣느라 각 버튼이 약 29px 폭이고 요일·월은 9px다. 버튼 높이는 충분하지만 좌우 간격과 작은 글자는 개선할 여지가 있다.

권장: 5개 날짜와 더 보기, 또는 가로 스크롤 날짜 목록. 오늘·내일은 강조하고 월이 바뀌는 지점만 명확히 표시한다. 선택 요약은 `9월 30일(수) · 오후 2시 희망`처럼 짧고 읽기 쉽게, 확정 예약이 아니라는 설명을 가까이 둔다. 달력 선택 자체는 유지한다.

### 4) 작은 화면의 금액 카드와 제목 줄바꿈을 다듬는다

320px에서 두 금액 카드 폭이 약 115/153px로 달라지고 숫자의 윗선이 약 19px 어긋난다. 금액이 잘리는 것은 아니지만 비교가 덜 쉽다. 작은 화면에서는 같은 너비·같은 제목 높이를 확보하거나 세로형으로 전환한다.

완료 제목 `상담 화면 체험을 마쳤습니다`도 320px에서 마지막 `다`만 다음 줄로 내려간다. 한글 단어 단위 줄바꿈, 제목 크기·폭 조정으로 고립된 한 글자를 피한다.

### 5) 상담 중에는 상담 이동 버튼의 역할을 바꾼다

현재 모바일 하단의 가격+`상담 화면 미리보기` 버튼은 상담 작성 중과 체험 완료 후에도 계속 남는다. 같은 영역으로 다시 이동하므로 이 단계에서는 효용이 낮고 화면을 차지한다.

상담 영역에 들어오면 숨기거나 작게 접는다. 폼 안의 `입력 내용 확인하기`와 혼동될 새로운 제출 버튼을 중복 배치하지 않는다. 긴 확인창은 마지막 행동 버튼을 찾기 쉽도록 하단 행동 영역 또는 스크롤 안내를 보완한다.

### 6) 공유 화면과 내부 문서의 마감 품질

- 제목·설명 OG 메타는 있지만 `og:image`는 없다. 승인된 콘셉트 이미지로 공유용 대표 카드를 준비한다. 실제 카카오 공유 카드 결과는 이번에 시험하지 않았다.
- 금액·가격 설명은 hero/FAQ/pricing/footer/애니메이션 값에 나뉘어 있다. 현재 값은 일치하지만 다음 변경부터 하나의 기준 데이터에서 출력하면 오래된 값이 남는 일을 줄일 수 있다.
- 공통 폼은 새 파일로 분리됐지만 `styles.css`에 옛 상담 스타일이 남아 있다. 후속 정리 때 백업과 비교하며 제거한다. 지금 결과가 깨졌다는 뜻은 아니다.
- `CODEX-HANDOFF.md`의 오래된 실행 안내에는 현재 스냅샷에 없는 `DEVELOPMENT.md` 등의 링크가 있다. 최신 인수인계 요약에 현재 유효한 문서·실행 경로·점검 기록을 모아 두는 것이 좋다.

### 7) 입력 보정 규칙은 명확히 정한다

가상 번호 `010abc00000000`을 넣고 다른 항목으로 이동하면 `010-0000-0000`으로 바뀌고 확인창까지 진행됐다. 숫자가 아닌 문자를 모두 제거하는 현재 규칙 때문이다(`consultation.js:34`~36). 공백·하이픈 보정은 편리하지만 글자가 섞인 번호도 말없이 바꾸는 동작은 입력 실수를 놓치게 할 수 있다. 허용할 구분 문자와 재확인을 요구할 문자를 정하고, 변경된 번호를 확인 단계에서 분명하게 보여주는 방안을 권한다. 실제 번호 존재 확인이나 본인 인증을 지금 구현하라는 뜻은 아니다.

## 5. 코드·빌드 검사 결과

- `app.js`, `consultation.js`, `workflow-model.js`, `workflow.js`, `server.mjs`, `scripts/build.mjs` 문법 검사 통과.
- 기존 메모리 검사 9개: **8 통과 / 1 실패**. 실패는 신규+부재 후속 처리 누락.
- 추가 경계 검사 26개: **26 통과 / 0 실패**. 한국 날짜 경계·윤일, 필수 항목, 과거 일정, 종료 정리, 원문 사본, 동시에 같은 토큰 요청, 다른 문의 보존, 알림 이력 중복 등을 검사.
- 합계 35개는 이 두 메모리 검사 묶음만의 수치다. 사이트 전체 합격률이나 실제 서버 동시 요청 보장이 아니다.
- `node scripts/build.mjs` 통과. 처음 샌드박스에서 파일 복사 EPERM이 발생했으나 같은 명령을 승인된 실행으로 재시도하여 성공했다.
- `dist`는 공개 HTML/CSS/JS 5개와 이미지 5개. 운영 시안·docs·원본 기획 자료는 현재 산출물 목록에 없다.
- 로컬 서버는 127.0.0.1:4173의 기존 프로세스가 유지 중이었다. 추가 시작 시도는 이미 사용 중인 포트 오류로 종료됐다. 처음 상태 조회에서 서버 종료를 의심했지만 실제 포트 확인으로 정정했다. 현재 실행 불가 문제는 재현하지 못했다.
- 점검 마지막에 공개 페이지를 새로고침해 12개 본문 섹션과 초기화된 폼이 다시 나타나는 것을 확인했다. 임시 운영 탭은 닫고, 뷰포트 override는 해제했으며 기존 탭은 `#ownership`으로 돌려놓았다.
