# 마이롯지 PC·모바일 비교 검수 — 2026-10-09

## 1. 범위와 결론

최신 개발본 `github-sync/MyLodge_Business`와 분리된 모바일 검토실의 작업본을 비교했다. PC 1440×900을 기준으로 모바일 320×568, 360×640, 390×844, 414×896, 태블릿 768×1024, 가로 화면 844×390을 한국어·영어로 확인했다. 이번 변경은 로컬 개발본 및 검토실에 반영했다. 배포는 보류한다.

가로 넘침이 없다는 사실과 실제 읽기 편하다는 사실을 별도로 판정했다. 현재 폭 검사에서 가로 넘침은 없지만, 작은 보조 문구·푸터의 낮은 명도·자동 전환의 읽는 시간·장면별 높이 변화는 추가 보완이 필요했다. 이 네 항목은 수정했다. 영상 안에 포함된 글자의 축소와 태블릿의 긴 세로 흐름은 후속 디자인 항목으로 남긴다.

## 2. 검증 환경과 해석 주의

- 개발 홈페이지: http://127.0.0.1:4173/
- 모바일 검토실: http://127.0.0.1:4186/
- 검토실 iframe은 실제 CSS 레이아웃을 지정 크기로 렌더링한다. 휴대폰 기기 에뮬레이터나 실기기 검증은 아니다.
- iframe의 세로 스크롤바 때문에 390 설정의 실제 `clientWidth`는 380px, 320 설정은 310px이었다. 표의 설정 크기와 실제 내용 폭을 구분한다.
- `PC 화면에 전체 맞추기`는 검토실의 화면 표시 배율이다. 실제 CSS 글자 크기는 DOM의 계산값으로 측정하고, 모바일 핵심 구간은 100% 표시로 육안 확인했다.
- 어두운 배경 설정은 검토용 테마다. 삼성 인터넷·카카오 인앱 브라우저의 강제 색 반전과 동일하지 않다.
- 영문 200% 검증은 검토실의 글자 배율이다. OS 글꼴 확대·브라우저 전체 확대·핀치 줌 검증과 동일하지 않다.
- 늦게 로드하는 이미지는 화면에 오기 전 `naturalWidth=0`일 수 있다. 이를 이미지 오류로 분류하지 않았다. 각 구간으로 이동한 뒤 화면 안의 이미지 로드 상태를 별도로 확인했다.

### 원인과 구현 세부

- 푸터는 원래 마지막 열의 연락 안내에 적용되던 낮은 명도·이탤릭 규칙이, 단일 열로 바뀐 브랜드 설명에도 적용됐다. 모바일용 색상 규칙보다 선택자 우선순위가 높아 단순한 색 선언으로는 해결되지 않았다. 브랜드 푸터에 한정해 우선순위를 맞췄다.
- 슬라이드 높이는 고정 px로 지정하지 않았다. 큰 글자와 영문에서 본문이 길어져도 가장 긴 장면의 자연 높이를 사용한다. 비활성 장면이 공간 계산에 참여하지만 화면·접근성 읽기·키보드 초점에는 참여하지 않는다.
- 모바일 여부가 바뀌면 타이머를 다시 예약한다. 정지 상태는 유지한다. 사용자가 제거한 좌우 화살표는 다시 추가하지 않았다.

## 5. 추가로 발견한 후속 디자인 항목

### B1. PPT 영상의 글자 — 우선도 높음

비디오 자체에 제목이 들어 있으므로 본문 글자 확대 설정을 적용해도 영상 속 글자는 커지지 않는다. contain은 잘림을 막지만 넓은 영상이 작은 화면에 들어가면 글자가 작아지는 문제가 남는다. **모바일 전용 세로 영상 또는 HTML 제목 레이어**가 필요하다. 현재 멘트·영상 자산을 변경하지 않았다. 실기기에서 320/360/390 폭, 60–70대 사용자 기준으로 읽기 검토하고 결정할 항목이다.

### B2. 태블릿·가로 모바일의 세로 길이 — 우선도 중간

768 및 844 가로 화면에서 카드가 한 열이어서 큰 이미지가 연속으로 이어진다. 화면 잘림은 아니지만 PC에서 한눈에 비교하던 정보를 오래 스크롤해야 한다. 제안: 세로 태블릿은 카드 2열을 검토하되 카드 폭·영문 줄바꿈을 먼저 검증하고, 가로 휴대폰은 이미지 높이만 줄여 읽기 영역을 확보한다. 좁은 화면에 일괄 3열 적용하지 않는다. 이번에는 콘텐츠 누락 위험 없이 읽기 문제를 먼저 수정했다.

### B3. 어두운 환경과 로고 — 우선도 높음, 실기기 확인 필요

검토실 밝은/어두운 배경에서는 투명 로고와 밝은 받침이 정상이다. `color-scheme:only light`, filter none, normal blend로 보호돼 있다. 다만 강제 다크모드는 브라우저가 별도로 이미지를 바꾸므로 PC의 검토 테마로 통과 판정할 수 없다. 삼성 인터넷 강제 다크, 안드로이드 Chrome, 카카오 인앱, iPhone Safari의 밝은/어두운 모드에서 상단·하단을 각각 캡처해야 한다.

### B4. 화면 회전·글자 확대·주소창 높이 변화 — 우선도 중간

검토실 크기 및 200% 글자 검사에서는 가로 넘침이 없었다. 휴대폰의 주소창 접힘, safe area, 소프트 키보드, OS 확대는 추가 검증이 필요하다. 글자 200%에서 생활 슬라이드가 한 화면보다 높아지는 것은 내용 보존을 위한 정상 결과다. 읽는 동안 정지 버튼에 접근하려면 스크롤이 필요하므로 확대 사용자 대상 UX 평가가 필요하다.

### B5. 색상 대비와 애니메이션 — 우선도 중간

푸터의 실제 계산 색상이 흐린 문제는 수정했다. 나머지 사진 위 작은 eyebrow와 AI 이미지 표기는 장면마다 배경이 달라 전 구간 WCAG 대비 통과를 선언하지 않는다. 네온은 사용자 요청에 따른 눈에 띄는 강도다. 작은 화면에서는 여러 테두리가 동시에 움직여 본문 집중을 방해할 수 있으므로 장시간 읽기 관찰이 필요하다. reduced-motion 시 정지 처리 코드는 유지하며 실제 OS 설정 시험은 별도다.

### B6. 터치와 접근성 — 우선도 중간

주요 모바일 탭·헤더·정지 버튼의 크기는 확인했다. 비활성 생활 장면에는 inert를 추가했다. 미지원 언어의 비활성 버튼 40px을 활성 조작 실패로 분류하지 않았다. VoiceOver/TalkBack, 전체 키보드 순서, 초점 표시 및 메뉴 복귀는 별도 접근성 검수가 필요하다. 모든 접근성 기준 충족으로 해석하지 않는다.

## 6. 검증 기록

- 한/영 × 7규격 = 14개 조합: `scrollWidth === clientWidth`, 본문 h2/h3/p/li/button/figure의 활성 표시 영역에서 가로 초과 없음.
- 영문 200% × 320/390/768/844: 가로 초과 없음. 서비스 소개 32px 확인.
- 생활 슬라이드 390: 세 장면이 모두 476.28125px, 전체 stage 551.078125px. 자동 진행 전후 높이 동일.
- 영문 200%: 320에서 stage 약 1068px, 390 약 977px, 768 약 1021px, 844 약 1068px. 각 규격에서 세 장면의 높이 동일.
- PC/모바일 주요 제목·서비스 설명·치앙마이 설명 DOM 텍스트 배열 동일.
- 390에서 각 주요 구간으로 이동하여 화면 안 이미지 로드를 확인. 이 스크롤 검사의 화면 내 이미지 모두 complete/naturalWidth 정상. 화면 밖 lazy 이미지 미로드를 실패로 집계하지 않음.
- JS 구문 검사: app, editorial, consultation, workflow-model, workflow, server 통과.
- 기존 workflow 검사: 9/9 통과. 모바일 시각 검사의 대체로 사용하지 않음.
- 빌드: 공개 파일 169개 생성 성공. 마지막 CSS 변경 후 빌드 재실행.
