## 발견 사항

### 1 재연락 후속 처리 검증 우회 가능 — P2 수정 필요

근거: PM 검토 5절의 부재 후 재연락 일정/사유 요구, 개발순서 보고서 J10의 담당자 후속 처리.

위치: workflow-model.js 49~61행, 84~88행.

재현: DEMO-001 신규 문의에 담당자 A와 최근 연락 결과 ‘고객 부재’만 지정하고 저장. 상태는 신규로 두고 다음 일정·행동·미정 사유를 모두 비워 둔다.

실제 결과: 저장 성공. 미배정 목록에서 빠지고 재연락 필요 목록에도 들어가지 않는다. 문의 자체는 전체/신규 목록에 남지만 후속 업무 큐에서 놓칠 수 있다.

원인: 후속 항목 요구는 상태가 scheduled/active/retry일 때만 실행된다. contact=absent/requested와 status=new의 모순을 검사하지 않으며 재연락 큐는 status=retry만 조회한다.

권고: 부재·재연락 요청을 선택하면 재연락 상태를 제안하고, 저장 시 상태 조합 및 다음 일정 또는 사유를 검증한다. 종료·철회 예외는 별도 유지한다. 자동 변경 여부는 UI 선택이지만, 누락 가능한 조합은 막아야 한다.

### 2 첫 화면 예약 문구와 준비 상태 사이의 차이 — P2 문구 보완

근거: 플랫폼 기획 05절의 현재 상태 표시, 보고서 G 영역과 공개 문구 원칙.

위치: app.js 57행 hero-description.

‘떠나고 싶은 날 예약해 머무릅니다’는 첫 방문자에게 현재 예약 가능 또는 원하는 날짜 보장으로 읽힐 수 있다. 아래 회원 영역과 FAQ는 준비 중·예약 기준 미정으로 안내한다. 문구 간 차이를 줄이는 것이 좋다.

권고 예시: ‘한 채의 별장을 함께 준비하고, 정해질 이용 기준에 따라 머무는 생활을 구상합니다.’ 또는 기존 문장 바로 옆에 ‘예약 서비스 준비 중 · 이용 일정과 기준 미정’을 표시한다. 새로운 사업 조건을 확정하는 수정은 아니다.

### 3 시간 경과에 따른 화면 갱신 제한 — P3 보완 권고

위치: consultation.js 144~164행 및 focus/visibilitychange 처리, workflow.js 178~179행.

코드상 시간 재계산은 화면 조작, 창 복귀, 제출 등에 의존한다. 화면을 켠 채 아무 조작 없이 기다리면 선택 버튼이나 ‘오늘 연락/기한 경과’ 수치가 즉시 바뀌지는 않는다. 상담 확인 시에는 다시 검증하므로 과거 시각 제출을 그대로 허용하는 결함과는 구분한다.

권고: 분 경계 또는 다음 일정 시점에 상태를 갱신하되 입력·포커스·작성 중 상세를 유지한다. 선택이 만료되면 선택 요약에서도 재선택을 안내한다. 이 항목은 코드 검토 결과이며 시간 이동 브라우저 재현은 미실행이다.

## 기획에 있으나 별도 결정이 필요한 차이

- J03의 ‘연락 방법’ 선택은 없음. 현재는 휴대전화와 희망 시간만 받는 시안이다. 전화/카카오/문자의 실제 상담 채널을 정한 뒤 선택 항목을 넣거나 전화 상담으로 범위를 명시한다. 알림 수단과 상담 방식은 같은 의미가 아니다.
- J01의 일반 상담/방문 관심 같은 신청 목적 분류는 현재 상담 주제로 대체되어 있다. 방문 접수 운영이 없으므로 지금 확장할 필요는 없지만, 방문 관심을 추가하면 업무 종류를 별도 필드로 구분해야 한다.
- 초기 기획의 상담 상태 예시는 새 PM 검토안에서 담당자·상담 상태·종료 결과로 재구성되었다. 상태 이름이 원안과 다른 것 자체는 결함이 아니다. 승인 전 검토용 제안으로 관리한다.

## 서버 보류 및 실제 공개 전 충족해야 할 조건

아래는 현 시안의 의도된 보류 사항이다. 현 단계에서 기능 누락 버그로 집계하지 않는다.

1. 실제 저장·접수번호·고객 확인·담당자 목록 연결: 현재 공개 폼은 체험이며 운영 연결은 별도 가상 폼만 가능.
2. 직원 인증·권한·서버 검증·동시 요청 중복 방지·처리 이력 보존: 메모리 시안은 운영 시스템을 대체하지 않음.
3. 회사 정보·공식 문의처·승인된 개인정보 안내·운영시간: 자료와 책임자 결정 필요. 현재 동의 화면은 체험 확인이며 정식 동의가 아님.
4. 가격 적용 상품·등기/이용권·추가 비용·모집 미달/취소·환불: 승인된 범위가 있어야 실제 상담형 공개로 전환 가능.
5. 실제 접수와 발송 실패, 무권한 접근, 모바일/키보드 등 공개 검수 사례: 전체 완료 기록 없음.
