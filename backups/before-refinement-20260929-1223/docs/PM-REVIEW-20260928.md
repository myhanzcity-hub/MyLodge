# 마이롯지 구현 기획 재검토

작성: 2026-09-28. 사용자 요청에 따른 기획 제안이며 사업·정책 승인이나 구현 완료를 뜻하지 않는다. 사이트 코드는 이번 검토에서 변경하지 않는다.

## 검토 근거와 방법

- 플랫폼 기획서 v0.1의 모집 우선 원칙, 상담·계약·이용권 구분과 상담 처리 흐름을 재확인.
- 홍보페이지 개발순서 보고서 v0.1의 첫 완성 흐름과 공개 기준을 재확인.
- 최신 CODEX-HANDOFF, app.js의 상담 입력·시간 선택·확인 처리, admin-demo.html의 목록·상태·저장 처리 코드를 대조.
- 고객, 담당자, 운영 책임자 관점으로 정상·변경·실패 사례를 서면 검토. 실제 사용자 조사나 실행 테스트 결과가 아니다.

## 1. 제품 목표

1차 목표는 고객이 공개된 조건을 이해하고 문의하며, 담당자가 상담 결과와 다음 행동까지 남기는 것. 한 건의 문의에 고객 입력, 담당자, 다음 연락 일정, 처리 이력, 종료 결과가 이어져야 한다.

상담 완료는 계약 완료가 아니다. 상담 건수, 참여 의사, 계약 인정 구좌는 별도 집계한다. 120구좌 집계는 계약 인정 정책 결정 후 연결한다.

## 2. 앞선 제안에서 수정할 판단

1. 폼에 관심 서비스까지 추가하면서 첫 문의의 부담이 커졌다. 관심 서비스는 추가 질문 영역에 접거나 상담 중 기록한다.
2. 정각 버튼은 희망 연락 시간을 확정 예약처럼 보이게 할 수 있다. 기본은 시간대 선호, 정확한 시각은 선택적으로 제공하는 안을 권한다. 전환 여부는 PM 결정 사항이다.
3. 운영자 상태를 늘리는 것보다 다음 행동과 기한이 먼저다. 담당 배정은 담당자 속성으로 관리하고 상담 상태와 혼합하지 않는다.
4. 프로젝트 비교는 실제로 다른 확정 정보가 생긴 뒤 만든다. 현재 미정 정보를 반복하는 비교표의 우선순위는 낮다.
5. 실제 문의가 없는 단계에서는 큰 관리 시스템보다 가상 문의 한 건을 고객→담당자→재연락→종료로 연결하는 시연이 먼저다.

## 3. 상담 입력 설계

첫 화면: 이름, 휴대전화, 관심 프로젝트(선택), 승인된 개인정보 안내와 동의. 프로젝트 카드에서 왔다면 관심 프로젝트를 미리 선택하되 사용자가 변경할 수 있게 한다.

‘상담에 도움이 되는 정보 추가’ 영역: 상담 주제, 관심 서비스, 희망 연락 시간, 문의 내용. 추가 정보 없이도 진행 가능해야 한다. 접힌 영역 안에 필수 입력을 숨기지 않는다.

흐름: 입력 → 연락처와 희망 시간 중심의 확인 → 접수 결과. 확인창 수정은 해당 필드로 돌아가며 나머지 입력을 보존한다. 반복 제출은 동일 접수로 처리하도록 서버 단계에서 설계한다.

개인정보를 브라우저 영구 저장소에 자동 보관하는 기능은 초기 범위에 넣지 않는다. 현재 데모는 실제 접수와 별도로 유지한다.

## 4. 시간 선택 설계

### 선택 의미

- 미지정: 고객이 시간 선호를 알려주지 않음.
- 시간 무관: 고객이 운영시간 중 연락 가능하다고 명시함.
- 희망 시간대: 특정 날짜와 승인된 시간대 선호.
- 희망 시각: 필요한 고객이 구체적 시각을 추가로 지정.

미지정을 ‘언제든 가능’으로 자동 변환하지 않는다. ‘담당자와 협의’는 전화 가능 시간이 별도로 없는 한 시간 무관과 기능이 겹쳐 독립 필수 선택지로 두지 않는다.

### 화면 제안

시간 무관 / 날짜·시간대 선택 → 오늘·내일·가까운 날짜·달력 → 승인된 시간대 버튼 → 필요한 경우 ‘구체적인 시간 선택’. 선택 결과는 한 줄로 계속 보인다. 실제 확정 예약을 도입하기 전에는 ‘희망 시간이며 담당자 확인 후 안내’라고 설명한다.

### 동작 기준

- 날짜 변경 시 이전 시각을 해제하고 재선택 안내.
- 시간대 탭이 단순 목록 필터라면 선택된 시각을 요약에 계속 표시하고 해당 시간대에 선택 표시를 남긴다. 시간대 변경 자체가 값 변경이라면 기존 시각을 해제한다. 두 의미를 섞지 않는다.
- 당일 이미 지난 시각은 실제 접수 전 선택 불가 처리하는 안을 권한다. 마감 버퍼·휴무일·종료시각은 운영 담당자가 정한다.
- 날짜 경계를 넘겨 화면을 열어둔 경우 선택·제출 시 한국 시간 기준으로 다시 확인한다.
- 운영 종료 후 ‘오늘 가능’으로 오해시키지 않는다. 다음 연락 가능일은 승인된 운영 달력에 따른다.
- 화면에 없는 시각을 직접 전송해도 서버가 허용 기준을 다시 확인해야 한다.

현재 09~23시는 시안 목록이다. 실제 운영시간이나 응답 보장으로 채택하지 않는다.

## 5. 운영자 업무 설계

첫 화면의 업무 묶음: 미배정 / 오늘 연락 / 기한 경과 / 재연락 필요. 단순 최신순 목록보다 업무 누락을 찾기 쉬운 구성을 권한다.

별도 속성:

- 담당자: 미배정 또는 담당 직원.
- 상담 상태: 신규, 연락 예정, 상담 중, 재연락 필요, 종료.
- 종료 결과: 안내 완료, 참여 검토, 고객 철회, 중복 등 승인된 값.
- 다음 행동: 누가, 언제, 무엇을 할 것인지.
- 고객 희망 시간과 담당자의 실제 연락 일정: 별도 필드.

재연락 필요로 저장할 때 다음 연락 예정 또는 일정 미정 사유를 요구한다. 부재는 상담 완료로 처리하지 않는다. 종료 시 종료 이유를 남긴다. 계약 전환은 별도 업무로 넘기며 구좌를 자동 증가시키지 않는다.

상세 화면: 고객의 원래 입력 / 담당자의 다음 행동 / 변경 이력. 처음 받은 입력을 직원 메모로 덮어쓰지 않는다.

운영 시안의 보완점: 문의 전환 전 미저장 메모 경고, 필터에 맞지 않는 상세가 남는 경우 명확한 표시 또는 상세 해제, 담당자·상태·메모 실제 변경 내역만 이력 기록, 빈 필터 결과 안내.

## 6. 접수·알림·고객 확인 분리

문의 저장 성공을 접수 성공으로 판단한다. 알림 발송 실패가 접수 실패가 되지 않게 한다. 담당자 화면에서 접수 상태와 알림 상태를 따로 본다.

고객 알림에는 필요한 최소 정보만 포함한다. 자세한 문의 열람·수정은 본인 확인이 가능한 경로로 제공한다. 접수번호 하나만 안다고 다른 고객의 정보가 열리는 구조를 만들지 않는다.

초기 발송 범위 제안: 고객 접수 확인, 담당자 신규 문의, 확정된 연락 일정 변경. 홍보·이벤트 알림은 후속으로 분리. 채널·비용·발송 조건은 PM 협의 대상이다.

## 7. 공개 정보의 신뢰 관리

승인된 프로젝트 정보마다 갱신일과 담당자를 관리한다. 가격·납입·권리·이용 조건은 한 기준으로 화면과 상담 안내에 반영한다. 조건이 바뀌면 이전 안내 버전도 내부에서 확인할 수 있어야 한다.

AI 콘셉트 사진은 현재 표시를 유지한다. 실제 자료가 준비되면 실제 현장, 확정 설계, 콘셉트를 나눠 제공한다. 회사 정보와 문의처가 계속 준비 중이면 실제 상담 공개 준비가 끝난 것으로 보지 않는다.

| 상황 | 기대 동작 | 필요한 작업 |
|---|---|---|
| 날짜를 고르다 그만둠 | 필수처럼 가로막지 않고 선택 해제 안내 | 선택 사항의 부분 입력 정책 |

| 오늘 이미 지난 시간 선택 | 가능한 시간 재안내 | 운영시간·당일 마감 정책 |

| 전송 응답이 늦어 다시 누름 | 접수 한 건만 생성 | 중복 방지·결과 조회 |
| 저장 성공, 문자 실패 | 접수 유지·발송 재처리 | 접수/발송 상태 분리 |
| 담당자 부재 또는 고객 부재 | 대체 담당 또는 재연락 일정 | 책임자·다음 행동 |
| 같은 사람이 다른 프로젝트 문의 | 별도 문의로 보존하고 연결 표시 | 전화번호만으로 중복 삭제 금지 |
| 문의 A 메모 작성 중 B 클릭 | 메모 소실 전에 확인 | 시안의 미저장 보호 |
| 상담 종료 | 결과 기록, 계약 건수 변화 없음 | 상담/계약 경계 |

위는 요구사항 검토이며 실행 테스트 결과가 아니다.

## 9. 구현 순서와 완료 기준

### 지금: 서버 없이 보완

폼 단순화, 시간 선택 규칙 정리, 수정 이동, 운영자 다음 행동·미저장 보호, 연결된 가상 문의 시연. 실제 개인정보를 시연 데이터로 넘기지 않는다. 가상 데이터를 명시적으로 선택한 시연에서만 동일한 예시 문의가 고객·운영자 화면에 이어지게 한다.

완료 기준: 가상 문의 한 건을 입력 확인부터 담당 배정, 부재, 재연락 일정, 종료 결과까지 따라갈 수 있고 어느 화면에서도 실제 접수로 표시하지 않는다.

### PM 승인 후: 실제 상담 접수

저장, 운영자 인증·권한, 처리 이력, 접수 결과, 알림, 중복 처리, 개인정보 처리 기준. 연락 목표 시간은 실제 인력과 운영일에 맞춰 승인받는다.

완료 기준: 고객 접수와 운영자 목록이 동일 건으로 연결되고 저장/발송 실패를 각각 처리하며 담당자 없는 문의가 방치되지 않도록 책임자가 정해져 있다.

### 실제 참여자 단계

계약·납입 확인과 진행 안내 → 이용권·예약 → 교환 → 렌트·정산 → 현장 서비스. 승인 정책과 공급 가능 상태가 각 단계의 선행 조건이다.
